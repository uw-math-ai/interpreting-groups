# Preregistration: P1B frame-versus-block regularization and capacity controls

Date: 2026-09-01. Committed before any run in this file is launched.
Handoff reference: Evidence-first final handoff, Sections 4.2 and 4.3.

## Question

Is the full SO(3) coefficient block's margin/norm advantage over the faithful
two-column frame a property of the wd = 1.0 cell only, or does it survive a
nontrivial regularization range and frame-favorable capacity?

## Existing cell (not rerun)

so3frame / so3block, wd = 1.0, seeds 0..4, 60k steps, batch 4096, lr 1e-3,
mlp_hidden 512, mlp_depth 1. Runs `data/su2/so3_{so3frame,so3block}_f0.01_s{0..4}`.

## New runs

### Stage 1: regularization sweep (30 runs)

    weight decay in {0.1, 0.3, 3.0}
    encodings in {so3frame (6D), so3block (9D)}
    seeds 0..4
    all other settings identical to the existing cell

Run names: `data/su2/so3_{enc}_wd{wd}_f0.01_s{s}`.

### Stage 2: capacity controls (20 runs, launched after Stage 1 finishes)

At wd = 1.0 (the existing primary cell), both arms with

    C1: mlp_hidden 1024, mlp_depth 1   (2x interaction width)
    C2: mlp_hidden 512,  mlp_depth 2   (one extra interaction layer)

seeds 0..4 each. These are frame-favorable in the sense that added
interaction capacity can only help the arm that must synthesize its missing
column; the block arm receives the same budget. With shared widths the two
arms differ in trainable parameters only through the first encoder layers
(2 x 256 x 3 = 1536 of about 3 x 10^5, under 0.6%), which we declare as
parameter-matched.

Run names: `data/su2/so3_{enc}_cap{h}x{d}_f0.01_s{s}`.

## Endpoints

Norm functionals, declared here:

    module norm      Frobenius norm of all parameters in a module
    total norm       sqrt(sum over modules of module norm squared)
    product norm     product of the three module norms (scale-sensitivity
                     diagnostic; the network is not homogeneous, so neither
                     total nor product norm is parameterization-invariant,
                     and both are reported as measured functionals only)

Primary endpoint:

    paired (by seed) difference in held-out T2 margin at matched total norm,
    read from the full logged trajectories (margin_T2, norm_enc, norm_int,
    norm_encc every 1000 steps), conditional on both arms reaching T2
    accuracy >= 0.85 at 60k steps.

Secondary endpoints:

    T2 accuracy at 60k; total and product norm at 60k; margin/total-norm at
    60k; steps to T2 >= 0.85; final train loss; module-wise norm allocation;
    Pareto frontier of margin against total norm over the trajectory.

Checkpoint rule: all endpoint values at the common final step 60k, plus full
trajectories; no per-arm post-hoc checkpoint selection.

Uncertainty: exact paired sign-flip permutation test over the 2^5 = 32
assignments (report the exact p), plus a paired bootstrap interval
(10^4 resamples) as descriptive uncertainty. All five paired values are
published. No asymptotic normality assumption.

## Decision rules (declared before launch)

    D1  Block margin advantage at matched norm holds with exact paired
        permutation p <= 0.0625 (the one-sided floor attainable at n = 5) in
        at least three of the four wd values, and no wd value reverses the
        sign: claim an advantage over a nontrivial regularization range.

    D2  Advantage only at wd = 1.0: scope every cost claim to that setting.

    D3  Pareto frontiers cross within a wd cell: reject a scalar
        "block is cheaper" claim for that cell and report the tradeoff.

    D4  Either arm fails the 0.85 accuracy floor in a cell: that cell is an
        optimization failure and contributes no cost evidence.

    D5  Capacity controls: block advantage survives C1 and C2 at wd = 1.0 ->
        architecture-robust evidence. The frame closes the frontier in C1 or
        C2 -> the wd = 1.0 result is an architecture-efficiency result and is
        reported as such. The frame exceeds the block -> the strong causal
        explanation is rejected.

## Failure criteria

Any run that diverges (final train loss above 1.0) or fails the accuracy
floor is reported, not discarded. If more than one seed per cell fails, the
cell is declared unusable and the grid is not extended post hoc.
